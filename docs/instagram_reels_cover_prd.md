# PRD — AI 인스타그램 릴스 표지·캡션 생성 웹서비스

- 문서 버전: v1.0
- 작성일: 2026-10-29
- 개발 대상: Next.js 기반 웹앱 / GitHub 소스 관리 / Vercel 배포
- 개발 실행 환경: Codex + VS Code
- 우선순위: MVP 먼저 구현 → 품질 검증 → 배포

## 1. 서비스 개요

사용자가 **스크린샷 2장**을 업로드하면 OpenAI API가 화면 내용을 분석하여 **3줄 제목 후보 5개**와 **새로운 인스타그램 캡션**을 생성한다. 첫 번째 스크린샷의 **핵심 사진·피사체·장면만 시각적으로 참조**하여 9:16 세로 이미지를 새롭게 생성한다. 사용자가 고른 제목을 이미지 위에 정확하게 3줄로 배치하고 수정한 뒤 최종 표지 이미지를 다운로드한다.

> 중요한 구현 원칙: AI 이미지 생성에는 제목 글자를 넣지 않는다. **이미지 생성(OpenAI API)**과 **한글 텍스트 오버레이(Canvas/SVG)**를 분리하여 글씨의 오탈자, 위치, 줄바꿈을 안정적으로 제어한다.

### 1.1 입력 이미지의 역할

| 입력 | 역할 | 분석 내용 | 결과 활용 |
|---|---|---|---|
| 캡처 이미지 1 | 영상 표지의 원본 비주얼 | 핵심 피사체, 상황, 배경, 사진 영역, 스크린샷 UI·문구 영역 구분 | 텍스트·앱 UI 없는 새 세로 배경 이미지 생성 및 제목 소재 |
| 캡처 이미지 2 | 캡션 원문 | 화면에 표시된 게시물 설명, 해시태그, 핵심 내용, 말투 | 새로운 인스타그램 캡션 작성 및 제목 후보 보강 |

- 캡처 이미지 1에서 **사진 영역을 분리·복원**하는 것이 목표다. 단순 캡처 확대나 SNS UI를 포함한 합성이 아니다.
- AI는 이미지 1의 내용을 참조하여 새로운 이미지를 만든다. **원본과 픽셀 단위로 동일한 추출은 보장하지 않는다.** 픽셀 보존 추출이 필요한 경우, 사용자가 자르기 도구에서 사진 부분을 지정할 수 있게 한다.
- 이미지 2에 캡션이 잘리지 않고 보여야 가장 정확하다. 누락되거나 판독이 불확실한 부분은 임의로 지어내지 않고 사용자에게 교정 가능하게 한다.

## 2. 핵심 사용자 플로우

1. 시작 화면에서 이미지 1(비주얼 스크린샷), 이미지 2(캡션 스크린샷)를 각각 업로드한다.
2. 사용자가 **분석 및 제목·캡션 생성** 버튼을 누른다.
3. 서버가 OpenAI 비전 기능을 통해 두 이미지에서 장면과 캡션을 읽는다. 인식한 캡션 원문은 편집 가능한 텍스트로 표시한다.
4. OpenAI 텍스트 모델이 **3줄 × 각 줄 3어절의 제목 후보 5개**와 새로운 캡션을 만든다.
5. 사용자는 제목 후보 한 개를 선택하거나 세 줄을 직접 수정한다. 캡션도 수정 가능하다.
6. **배경 이미지 생성** 버튼을 누르면 OpenAI 이미지 생성 API가 이미지 1을 참조해 텍스트 없는 9:16 이미지를 만든다.
7. 편집 화면에서 3줄 제목의 위치·크기·폰트·정렬·색상·그림자를 조정한다.
8. **PNG 다운로드**로 1080×1920 표지를 저장하고, **캡션 복사** 버튼으로 캡션을 복사한다.
9. 재생성 버튼을 이용해 제목만 다시 만들거나 배경만 다시 만들 수 있다(각각 별도 API 호출 및 비용).

## 3. MVP 기능 요구사항

### 3.1 이미지 업로드

- 두 개의 드롭존을 구분한다: `① 이미지 소재 스크린샷`, `② 캡션 스크린샷`.
- JPEG, PNG, WEBP 지원. 파일 크기 예시 제한: 각 10MB(운영 설정으로 조정).
- 미리보기, 삭제, 교체, 드래그 앤 드롭, 모바일 파일 선택 지원.
- EXIF 방향을 정규화한다. 원본 해상도·비율을 확인하고 필요하면 서버 전송용으로 축소한다.
- 서로 바뀌어 업로드한 경우 교환 버튼 제공.
- 이미지 1에서 사진 영역을 지정할 수 있는 **선택적 수동 크롭** 지원(자동 분리 실패에 대비).

### 3.2 AI 비전 분석 / 캡션 추출

- 서버에서 OpenAI API에 이미지 1, 이미지 2를 입력한다.
- 이미지 1: 장면 설명, 주요 피사체, 사진 영역 경계, 제거해야 할 UI/글자, 배경 재생성 지침을 구조화해 출력.
- 이미지 2: 화면에 실제 보이는 캡션 원문, 해시태그, 잘림 여부, 판독 불확실한 부분을 구분.
- **텍스트 추출 결과는 반드시 사용자 화면에 표시하고 수정할 수 있어야 한다.**
- 텍스트가 잘렸거나 가독성이 낮으면 경고와 직접 입력 옵션 표시.
- 외부 사실은 원문에 근거한 것만 사용하고, 수치·인물·지명·일시를 임의 추가하지 않는다.

### 3.3 제목 생성 — 정확히 5개

- 각각 **3줄**, **각 줄 3어절**, 전체 9어절. 예: `이건 정말 놀랍다` / `알고 보면 쉬운` / `돈 버는 비밀`.
- 여기서 '3단어'는 **띄어쓰기 기준 3개 어절**로 정의한다. 한국어 형태소 개수를 기준으로 하지 않는다.
- 제목 5개는 서로 다른 후킹 전략 사용: 호기심, 반전, 문제제기, 실용적 혜택, 직설적 핵심.
- 자연스럽고 짧으며 모바일에서 읽기 쉽게 작성한다. 의미 없는 과장·낚시·거짓 정보 금지.
- 단어 사이 공백 하나로 정규화; 공백 기준 각 줄 3개인지 검증.
- 모델이 규칙을 어길 경우 자동 재검증/재요청(최대 2회); 끝내 실패하면 편집 화면에서 검증 메시지를 표시하고 재생성 유도.
- 선택 후 사용자 수정 지원. 기본 편집도 3어절 규칙 위반을 경고하지만, 사용자가 의도적으로 다르게 배치할 수 있도록 경고와 차단 정책을 분리한다(MVP: 경고 후 저장 허용).
- 별도의 `제목 5개 다시 생성` 버튼 제공.

### 3.4 신규 캡션 생성

- 캡처 2의 캡션을 **그대로 복사하지 않고** 핵심 사실을 유지하며 자연스럽게 재작성한다.
- 기본 구성: 첫 문장 후킹 → 핵심 설명 2~4개 문단 → 댓글/저장 유도 문장 → 관련 해시태그.
- 원문의 톤을 참조하되 사용자 편집 가능. 해시태그는 원문 및 본문과 관련 있는 것만 제안한다.
- 원문에 없는 수치·뉴스·제품 효능·법적 사실을 꾸며 쓰지 않는다.
- `캡션 복사`, `캡션 다시 생성` 버튼 제공.
- 캡션 결과와 제목 결과는 같은 콘텐츠의 맥락을 공유해야 한다.

### 3.5 AI 이미지 생성 / 리디자인

- 이미지 1을 시각적 레퍼런스로 OpenAI 이미지 생성/편집 API를 사용한다.
- 생성 결과는 **세로 9:16**. 이미지 API의 지원 출력 비율이 다를 수 있으므로 API의 유효한 지원 크기로 먼저 생성하고, 필요한 경우 피사체 중심 스마트 크롭/패딩으로 최종 1080×1920에 맞춘다. 억지 늘리기는 금지한다.
- 원본 장면의 정체성·색감·분위기·핵심 요소를 최대한 유지하되, 필요한 배경은 자연스럽게 확장한다.
- 원본 스크린샷의 앱 UI, 아이콘, 워터마크성 오버레이, 댓글 인터페이스, 글자를 **새 이미지에 재현하지 않도록** 프롬프트에 명시한다.
- 원본의 로고나 저작권 표시 제거가 적절하지 않은 경우는 소유·이용 권한을 확인하게 한다. 사용자에게 업로드 이미지 사용 권한 확인 문구 제공.
- AI 생성 이미지에 텍스트를 그리도록 요청하지 않는다. **제목은 별도 렌더링**한다.
- 1안 생성이 MVP 기본값. `배경 다시 생성` 버튼 제공.
- 작업 중 로딩 및 오류/재시도 표시. Vercel 실행 시간 제한에 걸릴 수 있는 장시간 작업은 비동기 잡/폴링 방식으로 설계(아래 6장).

### 3.6 이미지 내 3줄 제목 오버레이

- 기본 출력 캔버스: 1080×1920 px, 9:16.
- 세 줄을 정확히 나눠 렌더링한다. 자동 줄바꿈 금지(각 줄 개별 레이어 또는 명시적 개행).
- 기본값: 화면 중앙 하단 영역, 큰 볼드 한글, 밝은 색 + 어두운 그림자/반투명 그라디언트.
- 편집 옵션: 폰트, 글자 크기, 굵기, 행간, 자간, 색상, 그림자, 외곽선, 정렬(좌/중/우), X/Y 위치, 드래그 이동.
- 모바일 미리보기 및 상하 안전 영역 가이드 제공. 주요 얼굴·제품 위로 글씨가 겹칠 때 사용자가 이동 가능.
- 한글 폰트: 라이선스가 명확한 웹폰트 사용(예: Pretendard 대체안 포함, 배포 전 라이선스 확인).
- 렌더링은 브라우저 Canvas/Konva 또는 SVG 기반. 최종 내보내기에서 폰트를 모두 로드한 뒤 이미지 생성.
- 고해상도 PNG(1080×1920) 필수. JPEG 선택 내보내기는 후순위.

### 3.7 다운로드 / 저장

- `표지 PNG 다운로드`: 파일명 예시 `reels_cover_20261029_001.png`.
- `캡션 복사`: 클립보드 복사. 실패 시 수동 복사 UI 제공.
- `제목 복사`: 현재 선택된 3줄 제목 복사.
- MVP에서는 회원가입·프로젝트 영구 저장 없이 브라우저 세션 상태 중심. 새로고침 시 복구는 선택사항.
- 이미지·텍스트를 서버에 장기 보관하지 않는다. 임시 저장을 쓴다면 짧은 만료시간과 자동 삭제를 적용한다.

## 4. 화면 구성

### Screen A — 업로드
- 서비스 제목/한 줄 안내.
- 2열 업로드 카드(모바일 세로 배치): 이미지 1 / 이미지 2.
- `분석 및 콘텐츠 생성` 주요 버튼.
- 파일 형식, 용량, API 사용 시 비용 발생 안내.

### Screen B — AI 분석 및 카피
- 이미지 1 미리보기 및 인식한 장면 요약.
- 이미지 2에서 추출한 **캡션 원문 편집창** + 인식 품질 경고.
- 제목 5개 카드(카드 하나당 정확히 3줄, 클릭 시 선택).
- 새 캡션 편집창 + 복사 버튼.
- `제목 다시 생성` / `캡션 다시 생성` / `배경 이미지 생성`.

### Screen C — 표지 편집기
- 좌측: 9:16 미리보기 및 드래그 가능한 3줄 제목.
- 우측: 제목 편집(3개 입력칸), 폰트/크기/행간/색상/그림자/X-Y/정렬.
- 이미지 재생성 버튼과 진행 상태.
- `PNG 다운로드`, `캡션 복사`, `다시 시작`.
- 좁은 화면에서는 미리보기를 위로, 편집 컨트롤을 아래로 쌓는다.

## 5. 기술 스택 및 아키텍처

| 계층 | 제안 기술 | 이유 |
|---|---|---|
| 프런트엔드 | Next.js (App Router), React, TypeScript | Vercel 배포 편의성 |
| UI | Tailwind CSS, shadcn/ui 선택 | 빠른 화면 구축 |
| 이미지 편집 | Canvas + Konva 또는 Fabric.js | 정확한 텍스트 위치 및 PNG 출력 |
| API 서버 | Next.js Route Handlers (Node.js 런타임) | 비밀 키 은닉, 입력 검증 |
| AI 텍스트·비전 | **OpenAI API (Responses API + 이미지 입력 + 구조화 출력)** | 화면 이해, 캡션 추출, 제목·캡션 생성 |
| AI 이미지 | **OpenAI 공식 이미지 생성/편집 API** | 원본 시각 참조 기반 배경 생성 |
| 파일 처리 | Sharp (서버 측) | 리사이즈, 스마트 크롭, 이미지 포맷 정규화 |
| 배포 | GitHub + Vercel | CI/CD |
| 장기 저장 | MVP 제외 | 최소 구성과 개인정보 보호 |

**주의:** 사용자는 OpenAI API Key를 제공할 예정이지만, 이 문서나 GitHub에 API Key를 적지 않는다. 채팅에 노출시키지 말고 Vercel의 암호화된 환경변수와 로컬 `.env.local`에만 설정한다. 서버 사이드 API 호출만 허용한다.

### 5.1 OpenAI 모델 설정

- `OPENAI_TEXT_MODEL`: 이미지 입력 및 구조화 출력 지원 모델. 기본값은 배포 시 공식 문서 확인 후 선택.
- `OPENAI_IMAGE_MODEL`: 이미지 입력 기반 편집/생성을 지원하는 OpenAI 이미지 모델. 배포 시 공식 지원 모델과 가격, 요청 스펙 확인.
- `.env.example`에는 모델명 **예시/설정 자리표시자**만 포함하고 실키는 절대 포함하지 않는다.
- API 호출은 공식 `openai` Node SDK를 기본으로 한다. 이미지 API/Responses API의 지원 파라미터와 모델을 개발 시 최신 공식 문서로 확인한다.
- 동일한 API 키로 텍스트와 이미지 엔드포인트를 호출하되 조직/프로젝트의 권한 및 이용 가능 모델 여부를 확인한다.
- 현재 가격·속도·출력 비율을 하드코딩하지 않는다.

### 5.2 권장 처리 방식

```text
브라우저
  ├─ 스크린샷 1 업로드 ─┐
  ├─ 스크린샷 2 업로드 ─┼─ POST /api/analyze ─ OpenAI (비전+구조화 출력)
  │                    └─ 장면 분석 / 캡션 OCR 유사 추출 / 5개 제목 / 신규 캡션
  ├─ 제목 선택 및 수정
  ├─ POST /api/generate-image ─ OpenAI 이미지 생성/편집
  │                                 └─ 사진 같은 9:16 배경(문자 없음)
  └─ 프런트엔드 Canvas 오버레이 ─ PNG 1080×1920 다운로드
```

- 텍스트 응답과 이미지 응답의 데이터 흐름을 분리한다.
- 모델 텍스트 출력은 JSON Schema로 구조화하고 Zod로 서버에서 검증한다.
- API 호출량을 제한하기 위해 생성 버튼을 누를 때만 호출한다. 제목 카드 선택이나 글자 위치 변경에서는 AI를 다시 호출하지 않는다.

## 6. API 설계

### `POST /api/analyze`
- 입력: multipart/form-data `image1`, `image2`, `captionOverride?`, `tone?`.
- 처리: 이미지 유효성 확인 → OpenAI 이미지 분석 → 캡션 원문 인식 → 제목 5개/새 캡션 생성.
- 출력 JSON 구조:

```json
{
  "scene": {
    "summary": "첫 번째 캡처의 사진 장면 요약",
    "subject": "핵심 피사체",
    "visualPrompt": "기존 사진의 장면/분위기를 참조한 새 배경 생성 지침"
  },
  "sourceCaption": {
    "text": "두 번째 캡처에서 읽은 원문",
    "isTruncated": false,
    "uncertainSpans": []
  },
  "titles": [
    {"id": "t1", "angle": "curiosity", "lines": ["이건 정말 놀랍다", "알고 보면 쉬운", "돈 버는 비밀"]}
  ],
  "newCaption": "새로 작성된 캡션..."
}
```

- 실제 `titles` 배열 길이는 반드시 5. `lines` 길이는 반드시 3. 각 `lines[i]`의 어절 수는 반드시 3.
- 제목/캡션은 생성형 결과이므로 사람의 검토가 가능해야 함.

### `POST /api/generate-image`
- 입력: `image1`(또는 서버의 만료되는 임시 파일 ID), `scene.visualPrompt`, `crop?`, `styleOptions?`.
- 처리: 원본 화면의 핵심 장면을 참고해 텍스트 없이 배경 생성, 서버 측 해상도와 비율 정규화.
- 출력: 생성 이미지의 임시 URL 또는 바이너리(인증된 호출만). 생성 실패 시 사용자에게 오류 표기.
- 보안: 프롬프트 크기 제한, 파일 크기 제한, 서버 호출 제한.

### 선택적 엔드포인트
- `POST /api/regenerate-titles`: 구조화된 제목 5개만 재생성.
- `POST /api/regenerate-caption`: 수정된 원문 기반 캡션만 재생성.
- `GET /api/jobs/:id`: 비동기 이미지 생성이 필요할 때 상태 조회.

### 6.1 장시간 이미지 생성 처리

- 이미지 생성이 Vercel 함수 제한보다 오래 걸릴 수 있으므로, MVP부터 **작업 상태 추상화**를 두어 동기 → 비동기 전환 가능하게 설계한다.
- 동기 응답이 안정적으로 완료되면 간단한 구현 허용. 타임아웃이 발생하면 Vercel의 지원 함수 설정/실행 제한을 확인하고 **큐 + 워커 + 오브젝트 스토리지(예: Vercel Blob 등)**를 도입한다.
- 브라우저 닫힘이나 요청 중단 시 중복 과금 방지를 위해 버튼 중복 클릭 차단 및 요청 ID/중복 실행 보호를 구현한다.

## 8. 검증 로직과 예외 처리

- 업로드 2장이 모두 있어야 분석 가능.
- 지원하지 않는 형식, 10MB 초과, 손상된 파일은 업로드 단계에서 차단.
- 원문 캡션 미검출 → 사용자에게 직접 입력 요청.
- OCR 유사 인식 불확실 → 불확실 표기 + 수정 허용.
- 이미지 1에 사람/피사체가 흐릿하거나 일부 가려진 경우 → 충실도 한계 고지.
- 제목 5개 누락/3줄 위반/줄당 3어절 위반 → 서버 자동 재검증 후 재시도, 실패 메시지.
- 이미지 API 콘텐츠 제한/오류 → 상세 민감 데이터 노출 없이 친절한 오류와 재시도.
- OpenAI 키 없음/권한 오류/한도 초과 → 관리자용 로그와 사용자용 간결 메시지 분리.
- 캔버스 폰트 미로드/교차 출처 오류 → 내보내기 차단 및 회복 안내.
- 재생성 실패 시 이전 생성 결과 보존.

### 8.1 제목 규칙 검증 의사코드

function validTitle(lines: string[]): boolean {
  return lines.length === 3 && lines.every(
    line => line.trim().split(/\s+/u).filter(Boolean).length === 3
  );
}

## 9. 보안, 비용, 운영

- `OPENAI_API_KEY`는 서버 전용 Vercel Environment Variable로 설정한다. `NEXT_PUBLIC_` 접두어 절대 사용 금지.
- 로컬 `.env.local`은 `.gitignore`에 포함하고 실제 키를 README, PRD, 스크린샷, GitHub Issue, 채팅 로그에 남기지 않는다.
- **API Key를 제공하는 사람만 사용하는 관리자용 서비스**가 MVP 기본 전제. 공개 URL로 배포할 경우 인증 또는 접근 제어를 반드시 구현하여 제3자 호출 및 과금을 막는다.
- 인증 구현 전이라면 Vercel Deployment Protection 또는 서버 측 비밀번호 보호 등 보호 장치를 사용한다. 브라우저 코드만으로 검사하는 비밀번호 방식은 금지.
- API 단위 rate limit, 동시 요청 제한, 파일 크기 제한, 요청 타임아웃, 사용자별 일일 호출/비용 상한.
- 로그에 업로드 사진, 캡션 원문, API Key, 원본 바이트를 기록하지 않는다. 요청 ID, 지연, 토큰/호출량, 오류 종류만 저장.
- 외부 이미지/인물/콘텐츠의 사용·저작권 및 개인정보에 대한 사용자 확인 문구 제공.
- OpenAI 모델별 요금과 생성 이미지 품질 옵션은 배포 직전에 공식 가격 문서로 확인한다.
- 기본적으로 원본 업로드는 요청 처리 후 삭제하고, 임시 이미지 사용 시 TTL 설정.
